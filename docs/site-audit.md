# Швидкодія та позиціонування oberemchuk.online

Перевірено 6 вересня 2026 року. Зміни підготовлено локально, сайт не опубліковано.

## Висновок

Знайдено реальні джерела зайвої роботи браузера: анімації великих блоків, розмиття тла, scroll-driven анімації з постійним `will-change`, зайві дані перекладів на кожній сторінці та надмірний обсяг каталогу. Головна також повторювала пояснення переваг, процесу й технологій. Це ускладнювало перегляд, особливо на телефоні.

Комерційна пропозиція була нечіткою: створення сайтів, технічне партнерство, вебпродукти, MVP, CRM, платежі та «ріст» подавалися майже рівнозначно. Це недолік структури й текстів. Скриншот Search Console не доводить, що саме він є єдиною причиною малої кількості показів.

## Підтверджені факти та виправлення

| --- | --- | --- |

| Довга головна | Окремі повторні блоки про переваги, навички, технології й процес | Замість них — компактний процес із трьох етапів; прибрано повторну секцію результатів |

| Аналітика | Модуль аналітики монтувався разом із рештою віджетів | Завантаження після початкової гідратації у вільний час браузера, з таймером як запасним варіантом. Правила згоди збережено |
| Мовні сигнали | Публічний HTTP `Link` задавав `x-default` на `/`, тоді як HTML і код sitemap задавали `/en` | Автоматичні мовні HTTP-посилання вимкнено; джерела — узгоджені HTML і sitemap. `/` стабільно український незалежно від cookie та Accept-Language |
| Зовнішній API | Для отримання портфоліо не було явного обмеження часу | Додано тайм-аут 8 секунд. Кешування збережено; при недоступності API залишається наявний порожній стан |

`public/LogoNew.png` важить близько 2 МБ, але поточна шапка використовує `Logo.svg`. Сам розмір невикористаного PNG не є доказом перевантаження сторінки.

## Нова структура

Основна пропозиція: **створення сайтів під ключ для бізнесу**.

- Головна: пропозиція → види сайтів і стартові ціни → роботи → процес → запитання → заявка.
- `/services`: лендінг, корпоративний сайт, інтернет-магазин; додатково — оновлення, підтримка й інтеграції.
- `/services/landing-pages`, `/services/corporate-websites`, `/services/ecommerce-development`: окремі сторінки конкретних послуг.
- `/portfolio`: приклади реалізації.
- `/estimate`: попередня оцінка вартості сайту.
- `/solutions` і `/blog`: допоміжний контент навколо створення та розвитку сайтів. У навігації прибрано технічну назву «SEO-сторінки».

H1, title, description, основні тексти та каталог структурованих даних узгоджено українською, англійською й італійською. Кольори, шрифти, округлення та загальний візуальний характер збережено.

## Вимірювання

Порівняння публічної версії з локальною production-збіркою. КБ — десяткові. HTML включає серверну розмітку й дані React. Gzip розраховано однаковим алгоритмом локально для обох відповідей; це не вимірювання фактичного CDN Brotli-трафіку.

| Сторінка | HTML до | HTML після | Зменшення | Gzip до → після |
| --- | ---: | ---: | ---: | ---: |
| Головна | 297,1 КБ | 232,5 КБ | 21,7% | 48,4 → 36,4 КБ |
| Послуги | 346,4 КБ | 127,3 КБ | 63,2% | 42,2 → 19,2 КБ |
| Портфоліо | 324,2 КБ | 264,6 КБ | 18,4% | 55,8 → 41,0 КБ |

У Chrome 1440×900 кількість елементів після відображення головної змінилася з 763 до 630, послуг — з 978 до 356. Активних анімацій у перевіреному стані головної: 13 → 0; елементів із `will-change`: 17 → 0. Це CSS-підказки браузеру, а не виміряна кількість фізичних GPU-шарів.

Ці цифри **не означають прискорення взаємодії на такий самий відсоток**. Значення довгих завдань головного потоку між запусками коливалися; в окремих запусках локальна головна мала довше завдання, ніж публічна. Тому покращення LCP/INP або CPU-часу цими тестами не доведено. Прибрано конкретні джерела постійної роботи та зменшено обсяг контенту. Для оцінки реального приросту потрібні повторні однакові тести після публікації та польові дані Core Web Vitals.

Публічна версія й робоча папка не ідентичні: наприклад, публічний sitemap містив 132 URL, локальний — 144. Дані портфоліо надходять із зовнішнього API. Порівняння не є ізольованим експериментом лише однієї зміни.

## Що перевірено

- Production-збірка й TypeScript: успішно, 175 згенерованих сторінок.
- Основні сторінки: HTTP 200, один H1, canonical, чотири мовні альтернативи, відсутність noindex.
- Українська головна не змінює мову через англійські/італійські cookie чи заголовок браузера.
- Основний текст, послуги й контактний блок доступні без JavaScript.
- Desktop 1440×900 та mobile 390×900: немає горизонтального переповнення або необроблених помилок JavaScript на перевірених сторінках.
- Мобільне меню, перехід до контактів, введення у форму та вибір типу сайту в калькуляторі працюють. Заявки не надсилалися; серверний розрахунок і доставка листів не тестувалися.
- Перемикання української на англійську та перехід до наступного проєкту в слайдері перевірено в браузері.
- Невідомий slug послуги: Next.js може повернути потоковий HTTP 200 із `noindex`; тест перевіряє також цей випадок. Це задокументована поведінка [Next.js](https://nextjs.org/docs/app/api-reference/file-conventions/loading#status-codes).
- `git diff --check`: без помилок пробілів. Наявні до початку роботи зміни `package.json` і `package-lock.json` не змінювалися в межах аудиту.

Дані: [HTML](site-audit/html-results.json), [браузер](site-audit/browser-results.json). Перевірка HTML: `node --use-system-ca scripts/audit-html.mjs` при запущеному production-сервері на 3100. Браузерний сценарій `scripts/audit-browser.cjs` використовує Chrome та Playwright 1.51.1 із тимчасової папки `oberemchuk-audit-tools`, не додаючи залежності до проєкту.

## Що встановлено щодо Google

Публічна головна повертає HTTP 200 та кеш Vercel HIT. Robots дозволяє сканування, sitemap доступний, зміст головної присутній у HTML. Суцільного технічного блокування індексації цими перевірками не виявлено.

На наданому скриншоті за три місяці видно дуже мало показів і один доступний рядок запитів — «вартість розробки концепції». Це сигнал проблеми видимості, але не звіт про причини виключення URL з індексу. Одна фраза не встановлює, як Google класифікує весь сайт.

Після публікації потрібно перевірити в Search Console головну й три основні послуги: чи проіндексовано URL, який canonical обрав Google, дату останнього сканування, результат live inspection і причини виключення сторінок. Далі — повторно подати sitemap та оцінювати покази за сторінками й тематичними запитами. Без цих даних не можна чесно відокремити проблеми індексації від слабкого ранжування вже проіндексованих сторінок.

Google рекомендує використовувати зрозумілі назви й слова аудиторії у title, головному заголовку та текстах посилань — [Search Essentials](https://developers.google.com/search/docs/essentials). Основна тема сайту та користь для визначеної аудиторії є частиною рекомендацій щодо [корисного контенту](https://developers.google.com/search/docs/fundamentals/creating-helpful-content). Це підстава для змін структури; гарантії позицій вона не дає.
